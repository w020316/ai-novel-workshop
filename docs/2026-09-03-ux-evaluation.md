# 用户体验评估报告（UX Evaluation）

> 对象：AI 小说制作工坊 ｜ 视角：真实用户 + 产品经理双视角
> 依据：本阶段真实端到端体验（起 dev、创建项目链路、设定/大纲/章节流式生成、审校、导出），结合交付报告历史实测。

***

## 1. 核心用户场景体验记录（≥3 个）

### 场景 A：从零新建科幻小说并生成世界观（任务完成率：高）

- 流程：首页空态→点「新建小说」→填标题/题材/简介→提交→设定工坊→一键生成世界观。

- 观察：

  - ✅ 空态引导清晰（新建 + 去灵感），新用户入门明确。

  - ✅ 世界观 LLM 生成返回 6 字段结构，实时可用。

  - ⚠️ 生成依赖已配置 LLM（当前为免费 GLM）；若未配置会静默回退/提示，需告知用户「需先填 key」——见痛点 P1。

- 障碍：无阻断；耗时由模型决定，生成期无剩余配额提示。

### 场景 B：生成人物档案 / 大纲（剧情设计）

- 观察：人物 JSON 10 字段、剧情设计 JSON 完整落库；多稿择优（抽卡 3 版）与一致性修正闭环逻辑在编排器内自动完成。

- ⚠️ 角色/大纲生成后的「已锁定/可编辑」心智：部分字段缺批量编辑入口（视为迭代项）。

### 场景 C：逐章流式生成 + 审校 + 去 AI 味 + 导出

- 观察：

  - ✅ SSE 流式逐字渲染，全角标点完好（无乱码），可随时中断。

  - ✅ 一键扫描 AI 痕迹、读者冷读、投稿合规、历史版本回滚齐备。

  - ✅ 导出支持 TXT/MD/EPUB（含 SVG 封面+元数据）。

  - ⚠️ 空流曾 100% 静默→已修：现明确报错。⚠️ 导出 EPUB 需 jszip（已内置）。

- 障碍：章节较长时中途若模型限流会中断，客户端目前区分「主动中断」与「错误」后提示，体验基本顺畅。

## 3. 用户痛点（含改进方案与预期效果）

| #  | 问题                                  | 改进方案                                   | 预期效果             | 状态                     |
| -- | ----------------------------------- | -------------------------------------- | ---------------- | ---------------------- |
| P1 | 首次使用若未配置任何 LLM key，AI 功能不可用但不显性提示   | 首页/生成按钮旁做「LLM 就绪」徽标 + 配置指引；无 key 时明确解释 | 降低新手挫败，避免「点了没反应」 | ✅ 已落地                  |
| P2 | 大量子功能（扫AI/冷读/合规/版本/导出）集中在正文下方，移动端拥挤 | 正文头部响应式：移动端标题在上、动作按钮换行；操作栏 flex-wrap   | 窄屏任务完成率 ↑        | ✅ 已落地                  |
| P3 | 设定/大纲生成后编辑以自由文本为主，缺结构化校验            | 关键字段（如规则）加「一句话一条」提示与快速增删               | 减少误填、简化修改        | 待办（→已落地：多行粘贴拆分；题材模板填充） |
| P4 | 网络/模型限流导致长章节生成中断时，用户不知已保住多少正文       | 生成中断自动保留已产内容可即时保存（当前已中止即保留草稿）          | 长文创作安全感 ↑        | 已具备                    |
| P5 | 桌面端空白留白偏保守，视觉冲击弱                    | 首页 Hero（墨晕/印章/分层浮现）已落地，可推广到项目页头部       | 提升独特性与品牌感        | 首页完成                   |

## 4. 功能-需求差距分析

- 已对齐：设定→大纲→正文→审校→去AI→合规→版本回滚→导出，闭环完整。

- 差距：① 云端同步（无后端，本地优先，属功能取舍）；② 实时榜单（受反爬，降级为粘贴拆榜，如实标注）；③ 结构化设定编辑校验（见 P3）。
