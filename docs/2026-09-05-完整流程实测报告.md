## 二、发现的问题

1. **【环境级·重要】Gemini 本地不可达时 chat 路由 500，无跨 provider 故障转移**
   - 现象：本地网络连不上 Google（`ConnectTimeoutError` → 172.217.x.x），`/api/llm/chat` 在重试耗尽后直接 500（每次 ~32s）。开书包/世界观等此前「成功」实为本地启发式降级兜底，非 LLM。
   - 影响：仅本地/受限网络环境；线上 Vercel Gemini 可达未暴露。
   - 处置：本地 `.env.local` 已将 `LLM_PROVIDER_ORDER` 改为 `zhipu,gemini` 规避（线上未动）。
   - 后续建议：~~chat/generate-chapter 路由对**连接类错误**做 provider 级 failover~~ → **已实现**（`buildProviderChain` + `callWithProviderFallback`，连接错误自动切换下一家；429/5xx 不切换）。
2. **【已修复】本地 embedding 模型资源缺失**：`/models/Xenova/all-MiniLM-L6-v2/onnx/model_quantized.onnx` 加载 ERR_ABORTED，向量记忆走降级路径。已从 ModelScope（`Xenova/all-MiniLM-L6-v2` 镜像）下载完整模型资源（config/tokenizer/quantized ONNX，共约 23MB）放入 `public/models/`，随仓库分发、本地与 Vercel 均可离线加载；Node 冒烟验证通过（`scripts/smoke-local-embedding.mjs`，输出 384 维向量）。另：embedding 服务端降级已顺带修正为使用各 Provider 的 `defaultEmbeddingModel`（此前误传 chat 默认模型），并支持连接错误级 Provider 故障转移。
3. **【噪音·已排查收口 2026-09-05】** dev 环境 hydration mismatch 警告、`/@vite/client` 404、一条 `Invalid regular expression: missing /` SyntaxError——不影响功能。
   - **排查结论（transformers.js 排除嫌疑）**：复现实验（临时触发页动态 import `@xenova/transformers`，dev 模式真实浏览器）加载成功（`loaded: pipeline=function`），无任何正则报错；Node 原生加载同样通过。
   - **真实来源**：SyntaxError 出现在 Next.js 自带 react-dom 开发版编译产物（`next/dist/compiled/react-dom/cjs/react-dom-client.development.js` ~L25630，webpack eval 求值时）。该源文件为纯 ASCII、Node 解析通过，本地磁盘文件无损坏；报错文本/位置在多次运行间漂移（本次为 `Invalid or unexpected token`，伴随 `net::ERR_ABORTED` 流式响应中断），判定为 **dev 模式 eval 求值/HMR 的瞬态损坏，外部环境噪音**，非本项目代码问题。
   - **生产模式验证**：`next build` + `next start` 真实浏览器检查首页与 `/project/new`，控制台**零语法错误**、渲染正常。
   - `/@vite/client` 404：仓库代码零引用（rg 无匹配），为自动化浏览器环境的外部探测请求，与项目无关。
   - **处置**：无需代码修复；后续 E2E 若再遇 dev 控制台 SyntaxError 可忽略，以生产模式为准。
