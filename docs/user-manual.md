# AI 小说制作工坊 · 用户手册

> 版本：1.0 | 2026-09-01
> 产品定位：全流程 AI 小说创作工作台 · 数据 100% 存储在浏览器本地

***

## 1. 产品简介

「AI 小说制作工坊」帮助网文作者完成从**世界观设定 → 人物建档 → 文风配置 → 大纲规划 → 章节生成 → 记忆/伏笔管理 → 导出成品**的完整创作闭环。采用「人工轻度介入」模式：AI 负责生成与建议，作者掌控设定与最终文字。

**核心卖点**：本地优先存储（IndexedDB），隐私安全、数据不离机。

***

## 2. 快速开始

### 2.1 启动项目（本地）

前置：Node.js ≥ 18。

```bash
npm install
# 配置 LLM Key：复制 .env.example 为 .env.local 并填入至少一个 Provider 的 Key
npm run dev        # 开发模式 → http://localhost:3000
# 生产部署
npm run build && npm run start   # 默认 3000 端口，可用 -p 指定
```

> 至少配置一个 `DEEPSEEK_API_KEY` / `ZHIPU_API_KEY` / `QWEN_API_KEY` 才能使用 AI 生成功能。

### 2.2 三步走主线

1. **设定工坊**：世界观、人物、文风、题材模板
2. **大纲与章节**：创作工作台生成大纲，逐章生成
3. **记忆与导出**：查看一致性报告、管理伏笔、导出 TXT/Markdown/EPUB

## 3. 功能使用指南（按模块）

### M1 项目管理（首页）

- **新建项目**：首页「新建小说」，填写书名/题材/简介/目标字数/文风。

- **进入项目**：点击项目卡「进入」，查看项目仪表盘（进度、章节统计）。

- **归档**：不再创作可将项目归档；删除会连带清理相关数据。

### M2 设定工坊

| 页签  | 用途                          | 快捷方式                |
| --- | --------------------------- | ------------------- |
| 世界观 | 维护五位世界设定 + 规则               | 可「一键生成世界观」回填        |
| 人物  | 建档 + 人物关系图                  | 可 AI 生成人物草稿         |
| 文风  | 选择预设或上传样本文风                 | 含文风样例上传             |
| 题材  | 从 30 个题材模板选择                | 决定题材基调              |
| 起名  | 按类别/题材批量生成人名、地名、功法、门派、兵器、法宝 | 支持一键复制 / 收藏为灵感卡反哺创作 |

### M3 创作工作台

- **章节管理**：查看章节列表、新建/进入章节编辑。

- **章节编辑器**：流式生成正文，支持**停止生成**、**改写**、**续写**等干预。

- **生成模式（抽卡择优）**：章节生成前可在「单稿 / 抽卡3版」间切换。抽卡模式下并行生成 3 个候选正文，系统按**读者评分自动择优**推送（择优用确定性读者指标，不额外消耗大模型配额；代价是单次消耗约 3 倍生成 token）。

- **大纲页**：生成/维护章节大纲。

### M4 记忆管理

- **记忆浏览/编辑**：查看与修正系统记忆（长期设定 + 章节摘要 + 近期上下文）。

- **一致性报告**：展示写作前后设定一致性检测结果。

- **伏笔看板**：拖拽管理伏笔的位置与回调状态。

### M5 导出备份

- **导出**：支持 TXT / Markdown / EPUB 三种格式。

- **备份 / 导入**：JSON 全量备份，可跨浏览器恢复。

### M6 质量与追读保障（防烂文工具箱）

- **一键去AI味（定点修复）**：章节编辑器内先「扫描 AI 痕迹」，再「一键去AI味」。系统用 11 类确定性规则（无效空动作、总结旁白、转折词密集、模板套话、过度书面化、对话标签堆叠、「不是…而是…」句式、破折号、连续「了」字、超长段落、排比堆砌）定位命中句，**只改写命中句、其余正文原样保留**（定点修复，避免整章重写引入新问题）；修复明细会以「原句 → 改后」对照展示。

- **读者冷读复核**：以读者视角对当前章打分（0-100），评估开篇钩子、断章悬念、对话占比与节奏，给出「值得保留 / 建议改进」清单。

- **投稿合规体检**：投递/上稿前对当前章做一次性确定性离线自查（不消耗模型额度），涵盖：**高危内容**（不当性描写、毒品/违禁品、赌博、极端血腥）、**广告/引流**（站外链接、联系方式）、**格式/调试残留**（Markdown 符号、占位符、AI 自报/模板结尾）、**AI 痕迹密度** 与 **章节尺度/开篇断章**。输出 0-100「过审友好度」与「必改 / 需处理 / 通过」清单，便于投稿前逐项修缮。

- **卷级健康体检**：项目仪表盘全局体检——主线进度、伏笔积压/超期、角色遗忘、战力通胀、节奏厚度与**爽点密度（追读力）**；长期没有打脸/反转/扬名等 payoff 时刻会预警。

- **生成内置黄金三法则**：章节与剧情设计提示词已内置「展示而非讲述 / 冲突驱动 / 悬念承上启下（开头接钩子、结尾留断章）」，从源头降低 AI 味与流水账。

> 说明：体检仅作**自查提示**，并不承诺通过任何平台审核；最终是否符合各平台内容条款，请作者自行核对平台规则并负责。

## 4. AI 能力与模型配置

- 系统内置多 Provider（DeepSeek / 智谱 / Qwen）自适应，配置于 `.env.local`。

- 生成类操作均有 **loading 态并防重复点击**；长生成可用**停止**按钮中断。

- 若配了多个 Provider，主模型失败会自动尝试降级。

> 免费模型可能有速率/额度限制；部署公开访问时建议保持 `LLM_RATE_LIMIT_ENABLED=true`（默认）。

## 5. 常见问题（FAQ）

**Q1 生成没有反应？**
检查 `.env.local` 是否正确填入了至少一个 Provider 的 Key，且服务已重启（`npm run dev`）。

**Q2 为什么生成到一半停止了？**
可能触发免费额度速率限制或手动点击停止。可「重试」，已生成的正文默认保留。

**Q3 换个浏览器为什么项目没了？**
数据存在浏览器本地（IndexedDB），换浏览器/清缓存会丢失。请用「导出备份」定期保存，换环境后「导入恢复」。

**Q4 如何让记忆更准？**
在「记忆管理」中手动修正错误/过期的长期设定，系统会优先采纳人工修正。

**Q5 支持手机使用吗？**
支持。响应式适配移动/平板/桌面；创作工作台在移动端改为上下/标签布局。

**Q6 数据会上传到服务器吗？**
不会。项目数据全部在浏览器本地，仅在调用 AI 生成时把必要的提示词发送给所选大模型。

**Q7 把 AI 小说投到平台（番茄/起点/七猫等）被质疑「AI 制造」或过审难，怎么办？**
建议按以下流程降低 AI 痕迹：

1. 每章生成后先跑「扫描 AI 痕迹 + 一键去AI味」，再人工通读，把不符合人设的句子亲手改一遍（人工润色是最有效的「人味」来源）；
2. 用「读者冷读复核」检查开头钩子与结尾断章，追读指标差的章先改再投；
3. 用「卷级健康体检」确认没有流水账（升级通胀）、伏笔烂尾与角色断层；
4. 导出前核对题材与简介一致性，避免平台按「题文不符」驳回。
   本系统不承诺规避平台审核规则，请遵守各平台对 AI 辅助创作的条款。

**Q8 为什么「一键去AI味」后只有几句话变了？**
这是**定点修复**设计：只改写被规则命中的句子，其余正文原样保留，防止整章重写引入新的剧情或文风偏差。命中句会以「原句 → 改后」对照列出，不满意可手动再改。

## 6. 架构与技术栈（简介）

- **前端**：Next.js 15（App Router）+ React 19 + TypeScript + Tailwind CSS

- **状态**：Zustand；**本地存储**：Dexie.js（IndexedDB）

- **记忆体系**：三级（长期设定 / 向量章节摘要 / 近期上下文）+ TF-IDF/向量检索

- **AI 路由**：服务端代理（chat/embedding/generate-chapter）+ 限流 + Provider 降级

- **导出**：TXT / Markdown / EPUB（jszip）

详见 `docs/specs`、`docs/plans`、`docs/design`。
