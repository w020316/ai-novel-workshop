## 功能说明

长篇连载中后期，AI 生成章节的句式节奏 / 对话占比 / 用词偏好会悄悄偏离开篇建立的风格（「文风跑了」），读者最先察觉。本功能对「最近 5 章」与「基线指纹」做确定性对比，及时告警。

**入口**：记忆管理页 →「文风漂移监测」卡片 → 一键扫描。

## 设计要点

1. **纯函数、零 LLM / 零网络**（与世界状态机同模式）：`src/lib/style/drift.ts` 的 `detectStyleDrift`，结果确定性可测，不消耗 AI 额度。
2. **基线优先级**：文风预设（StylePreset 的 `vocabularyProfile` + `dialogueRatio`，开篇锚点）优先；无预设时聚合「此前全部章节」（最近 5 章除外，且需 ≥3 章）。
3. **三信号判定**（阈值常量可导出复测）：
   - 平均句长相对偏差率：≥20% watch，≥35% alert
   - 对话占比绝对变化：≥0.12 watch，≥0.20 alert
   - 高频词组重叠系数 |∩|/min：≤0.4 watch，≤0.2 alert
4. **重叠系数而非 Jaccard**：预设基线词组集（≤8 组）远小于近期统计集（~24 组），Jaccard 会结构性偏低导致恒误报。
5. **四级总评**：insufficient / normal / watch / alert（任一 alert 信号 → alert；否则任一 watch → watch）。
6. **顺带修复既有 bug**：`profile.ts` 对话提取正则开/闭类只含直引号 U+0022，中文弯引号 “” 与直角引号 「」『』全部漏检 → 对话比统计恒为 0。改为成对引号匹配（直引号+弯引号 / 直角引号 / 括号），既有用例（直引号）全部兼容。

## 过程教训（复现即避坑）

1. **并行 Edit 同一文件会互相覆盖**（本次 drift.ts、drift.test.ts 两次踩中，丢失部分编辑导致测试假红/假绿）：同文件多处修改必须串行 Edit。
2. **`slice(0, 负数)` 吞章节**：总章数 ≤ recentK 时 `slice(0, len - recentK)` 为负索引，会从头吞掉章节——已改为显式判断。
3. 周期性测试文本（循环字符 + 旋转偏移）的 top-N 词组取哪个子集取决于并列排序，测试预设词组应从首次扫描结果中取，不要手写猜测。
