## 一、功能概述

新建项目向导「AI 配置」步新增 **Ollama 本地** 供应商选项：项目可指定本地 Ollama 模型生成正文/设定/校验，零成本、离线可用，契合「只用免费资源」约束。

## 二、实现要点

| 项 | 说明 |
| --- | --- |
| 类型 | `LLMProvider` 增加 `'ollama'`（types/index.ts） |
| 协议 | 复用 `OpenAICompatibleAdapter`：Ollama 原生兼容 `/v1/chat/completions`、`/v1/embeddings`，流式 SSE 同构 |
| 默认配置 | `http://localhost:11434/v1`，模型 `qwen3:8b`，Embedding `nomic-embed-text` |
| 启用门控 | `OLLAMA_ENABLED=true` 或设置 `OLLAMA_BASE_URL` 即视为已配置；未启用时云端部署绝不误连 localhost |
| 免 Key | Ollama 无需 API Key，Bearer 头用占位值 `ollama`；`createAdapter('ollama')` 未启用时抛出带 `OLLAMA_ENABLED` 提示的错误 |
| 环境变量覆盖 | `OLLAMA_BASE_URL`（远程局域网端点）、`OLLAMA_DEFAULT_MODEL`、`LLM_PROVIDER_ORDER=ollama,...` |
| 降级兜底 | 默认 provider 序列尾部追加 ollama：云端 Key 全缺失 + Ollama 已启用 → 兜底可用；`createFirstAvailableAdapter` 同步 |
| UI | 向导第 3 步新增「Ollama 本地」单选 + 模型选项（qwen3:8b / llama3.1:8b / glm4:9b）+ 琥珀色部署提示（本地可用、Vercel 无法访问本机模型） |
| 503 文案 | chat / embedding 路由错误提示补充「或启用本地 Ollama（OLLAMA_ENABLED=true）」 |

## 三、设计取舍

1. **服务端代理而非浏览器直连**：全部 LLM 调用走 `/api/llm/*` Node 路由，无需 `OLLAMA_ORIGINS` CORS 放行；代价是 Vercel 等云端部署访问不到本机模型（UI 已明示）。
2. **opt-in 而非默认参与**：未启用时 `isProviderConfigured('ollama')` 恒为 false，云端部署行为与改动前完全一致，零回归风险。
3. **provider 级单模型链**：ollama 不套 gemini 的模型降级链（本地换模型意义不大），请求失败直接走既有 provider 级回退。

## 五、使用方式

```bash
# 本机安装并运行 Ollama
ollama serve
ollama pull qwen3:8b
ollama pull nomic-embed-text

# .env.local
OLLAMA_ENABLED=true
# 可选：远程端点 / 默认模型
# OLLAMA_BASE_URL=http://192.168.1.5:11434/v1
# OLLAMA_DEFAULT_MODEL=llama3.1:8b
```

新建项目 → 第 3 步 AI 配置 → 选择「Ollama 本地」即可。
