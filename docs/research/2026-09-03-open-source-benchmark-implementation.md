## 二、技术实现方案（可复用架构）

以下方案即本项目当前架构的抽象，可直接作为同类 AI 写作产品实现参考。

### 2.1 总体架构（数据 / 逻辑 / 展示三层）

```
┌── 展示层（Next.js 15 App Router + React + Tailwind）──────────────┐
│  首页 / 项目页 / 设定工坊 / 工作台 / 记忆 / 健康 / 多平台审稿 / 导出  │
└──────────────┬────────────────────────────────────────────────────┘
               │ 读/写（Dexie/IndexedDB，本地、无后端）
┌──────────────▼────────────────────────────────────────────────────┐
│  领域逻辑层（纯 TS，可单测）                                       │
│  ┌──────────┬────────────┬──────────────┬───────────────────────┐  │
│  │ 记忆      │ 生成编排     │ 审校/质检     │ 导出/合规              │  │
│  │ 三级记忆   │ 5 阶段流水线  │ 健康体检      │ TXT/MD/EPUB/JSON     │  │
│  │ 向量检索   │ 剧情/写作/    │ 冷读复核      │ 版权/商用合规          │  │
│  │ 伏笔登记   │ 一致性/重写   │ 多平台审稿     │ 版本回滚              │  │
│  │          │ 批量续写      │ 投稿合规      │ 拆书/全局灵感库         │  │
│  └──────────┴────────────┴──────────────┴───────────────────────┘  │
└──────────────┬────────────────────────────────────────────────────┘
               │ LLM 适配（OpenAI 兼容 + 降级 + 流式）
┌──────────────▼────────────────────────────────────────────────────┐
│  LLM 适配层：openai-compatible / client / fallback / providers     │
│  多 Provider（zhipu/deepseek/qwen） 自定义 BASE_URL/DEFAULT_MODEL   │
└────────────────────────────────────────────────────────────────────┘
```

### 2.2 关键设计决策与理由

| 决策 | 理由 |
|---|---|
| 浏览器本地存储（Dexie/IndexedDB）而非服务端 DB | 零部署成本、无账号、数据隐私；规模上量预留迁移 pgvector/Milvus 接口 |
| OpenAI 兼容适配 + 环境变量覆盖 | 一套适配器对接任意兼容 Provider，避免重复实现；`{PROVIDER}_BASE_URL` 支持自建网关 |
| 5 阶段流水线 + 记忆回溯 | 保证长篇连续（对比单次提示词拼接的长文断链痛点） |
| 一致性修正闭环 | 出现 error 级冲突自动触发定向重写（最多 2 次），降低"人设/伏笔崩坏" |
| 本地确定性规则优先、LLM 增强降级 | 拆书/冷读/合规/去AI味 即使 LLM 不可用也有可用结果，稳定可测 |
| 依赖注入的批量续写 | `generateChaptersBatch` 注入 single 生成器，便于单测不消耗真实 LLM |

### 2.3 扩展性 / 潜在风险与应对

| 风险 | 应对 |
|---|---|
| 数据本地独享、换设备不迁移 | 已提供 JSON 完整备份/恢复；后续可加"一键云同步"或"导入导出增强" |
| 百万字级文体一致性仍无成熟方案 | 依托伏笔登记 + 周期摘要压缩（我方差异化投入），已实现三级记忆累积 |
| AGPL 传染 | 参考思想、不搬源码；核心模块自研 |
| CN 模型字段/流式差异 | `LLMAdapter` 统一 normalizer + 超时重试 + 降级切换 |
