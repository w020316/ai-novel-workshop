## 二、发现的问题

1. **【环境级·重要】Gemini 本地不可达时 chat 路由 500，无跨 provider 故障转移**
   - 现象：本地网络连不上 Google（`ConnectTimeoutError` → 172.217.x.x），`/api/llm/chat` 在重试耗尽后直接 500（每次 ~32s）。开书包/世界观等此前「成功」实为本地启发式降级兜底，非 LLM。
   - 影响：仅本地/受限网络环境；线上 Vercel Gemini 可达未暴露。
   - 处置：本地 `.env.local` 已将 `LLM_PROVIDER_ORDER` 改为 `zhipu,gemini` 规避（线上未动）。
   - 后续建议：chat/generate-chapter 路由对**连接类错误**做 provider 级 failover（当前 resolveProvider 只按「是否配置」回退，不按「是否可达」）。
2. **【轻微】本地 embedding 模型资源缺失**：`/models/Xenova/all-MiniLM-L6-v2/onnx/model_quantized.onnx` 加载 ERR_ABORTED，向量记忆走降级路径，功能不受阻；如需完整本地向量可把模型文件放入 `public/models/` 或统一走服务端 embedding。
3. **【噪音】** dev 环境 hydration mismatch 警告、`/@vite/client` 404、一条 `Invalid regular expression: missing /` SyntaxError——不影响功能；regex 报错来源值得后续排查（疑似 transformers.js dev chunk）。
