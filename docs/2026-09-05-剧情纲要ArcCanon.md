## 1. 背景与目标

百万字长篇的中段最大风险是「剧情跑偏 / 前后矛盾」：三级记忆只注入近期摘要，
全书尺度上的「已发生剧情真值」缺失。本轮对标开源写作工具的 ArcCanon 思路，
新增一份随写随更的**剧情纲要**：把全书已发生剧情增量压缩成 800 字左右的
真值锚点，在每次生成新章时注入 prompt，强制 AI 与前情保持一致。

## 2. 方案设计

### 2.1 数据层
- 新类型 `ArcCanon`（src/types/index.ts）：canonText / upToDateChapterNo / fromLLM
- 新表 `arcCanons`（schema v7），id 固定 `canon_<projectId>`（一项目一份）

### 2.2 更新链路（随写随更）
- 编排：src/lib/memory/arc-canon.ts
  - `maybeUpdateArcCanon`：章节保存后判断「覆盖差值 ≥ 10 章」才触发增量压缩
  - `regenerateArcCanon`：全量重建（记忆页手动按钮用）
- 压缩：src/lib/llm/generators/arc-canon.ts
  - LLM 优先：旧纲要 + 新摘要 → 融合为更新版纲要（≤1500 字符）
  - 确定性降级：摘要按章号拼接，超长时从最旧摘要行开始裁剪、保留主线锚定头部
  - 失败静默（不阻塞章节保存与记忆更新主流程）

### 2.3 生成注入（防跑偏）
- `loadLongTermMemory` 加载 arcCanon（查询失败单独 catch 不拖垮装配）
- `memoryToPrompt` 在大纲之后注入「剧情纲要（已发生剧情的真值摘要，
  必须与前情一致，禁止矛盾/重演）」分区，并标注覆盖章号
- `estimateMemoryTokens` 同步计入 canonText（估算口径与注入一致）

### 2.4 UI
- 记忆页新增「剧情纲要」卡片（ArcCanonCard）：展示纲要全文（滚动）、
  覆盖章号、来源（AI 压缩 / 确定性拼接）、更新时间；手动「重新生成」
- 无纲要时空态引导：每写满 10 章自动生成，或立即手动生成

## 4. 已知边界

- 纲要质量依赖章节摘要质量（摘要 ≤300 字，自动截取正文开头）
- 触发粒度为 10 章；不足 10 章的中途修正可手动「重新生成」
- LLM 输出上限 1500 字符，超出截断（压缩 prompt 已要求 800 字内）
