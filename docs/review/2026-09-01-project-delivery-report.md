## 5. 源码审查建议（P3 优化项）

1. **多实例限流失效**：内存限流在横向扩容（多 Vercel/多副本）下各自独立。建议生产接 Redis 或使用第三方网关限流。
2. **敏感配置**：`.env.local` 含智谱与备用 API Key，请确保其被 `.gitignore` 排除且不入库。
3. **`assembler.ts` 顶层 import `useShortTermMemory`**（Zustand hook）被 pure 方法引用，混用了 UI 层与纯逻辑层；建议把短时记忆读取作为依赖参数注入，便于测试与解耦。
4. **`extractKeywords` 的 O(n²) 组装**（2/3/4 字全组合）：项目长文时耗时线性放大，建议限制输入长度或用分词库。
5. **LLM 路由缺少通用请求中间件**：3 个路由的鉴权/限流/请求体校验逻辑重复，可抽公共 helper 收敛。
6. **错误上报缺乏告警**：LLM 调用失败仅 `console.error`，建议接入可观测性（可选）。

## 6. 前端 UI 设计方案（墨韵书卷设计系统 · 已落地）

> 完整规范见 `docs/design/2026-09-01-design-system.md`（配色/排版/组件/响应式，与 `tailwind.config.ts`、`globals.css` 一一对应）。

### 6.1 色彩系统
- **主色 Brand·墨韵青**：`brand.500 #37806f` / `brand.600 #2a6658`，用于主按钮、焦点、选中态。
- **辅助 Accent·丹砂红**：`accent.500 #d34337` / `accent.600 #c0332c`，仅用于危险操作与点睛数据。
- **中性**：宣纸暖底 `paper.50 #fbf8f1`、卡片 `paper-50`、墨色正文 `ink #29231b`；覆盖 `stone` 冷灰为暖墨中性，全站色温统一。
- 使用规范：主色占比 ≤10%，用于强导向操作。

### 6.2 排版
- **界面字体**：`Noto Sans SC / Source Han Sans SC / 微软雅黑`；**标题与小说正文**：`Noto Serif SC / Songti SC`（文学衬线）。
- 正文行高 1.75、`letter-spacing 0.035em`（`.font-novel`）；标题 1.2~1.3、字重阶梯 h1~h4。
- 层级：业务标题 `font-serif text-xl~3xl text-brand-800`、正文 `text-stone-600`、辅助 `text-xs text-stone-400`。

### 6.3 核心组件
- **按钮**：主/次/危险/幽灵，触控 ≥40px，圆角，禁用 + loading 态（生成类按钮防重复点击）。
- **卡片**：宣纸底 `bg-paper-50` + 1px 描边 `border-stone-200`，圆角 12px，hover 轻提升阴影。
- **表单**：标签 + 输入 + 错误三态；聚焦 `ring-brand-500`。
- **进度/状态徽章**：对应章节状态（`ChapterStatusBadge.tsx`），项目卡进度条 `bg-brand-500`。

### 6.4 响应式规则
- 断点 `sm 640 / md 768 / lg 1024 / xl 1280`；桌面多栏 → 平板双栏 → 移动单栏，创作工作台移动端改为标签切换上下堆叠。

### 6.5 设计来源与差异化
- 调研参考：中文阅读产品（起点/晋江/微信读书）排版秩序、创作者工具（Notion/Obsidian）组件克制、文学感视觉（水墨/书卷）低饱和配色；GitHub 开源 UI 系统（shadcn/ui、Radix）实现参考。
- 差异化：以「宣纸质感背景 + 墨青主色 + 衬线标题 + 朱砂点睛」营造沉静书卷气，规避泛化 AI 视觉（紫色渐变/几何科技风）。

### 6.6 落地状态与提交
- **已落地**：`tailwind.config.ts`（color tokens）、`globals.css`（宣纸背景/字体/滚动条/选区）、`Card/Input/Button` 组件类名；首页与项目卡已采用新主题。
- 本次终版基于该规范提交（`c8b1acd`）。

## 7. UX 体验评测与改进建议

### 7.1 浏览器实测证据（真实操作）
> 环境：`next dev` 于 `http://localhost:3001`，浏览器自动代理实测。因每次会话为独立浏览器档案，索引库不跨会话共享，故分两次会话分别验证了不同场景。

**场景① 新建项目 —— ✅ 通过**
- 首页可访问，点击「创建第一部小说」进入新建表单；书名/题材/简介/字数/文风字段均可填写。
- 选择「科幻」题材 +「硬核爽文」文风，交互正常；点击创建后约 2 秒显示成功提示并跳转项目概览。
- 结论：表单字段齐全、步骤精简、有即时成功反馈，符合 PM 预期。

**场景② 设定配置 —— ✅ 通过**
- 进入设定工坊，点击「一键生成世界观」：按钮进入禁用/生成中状态，约 2~3 秒后填充 5 个字段 + 4 条规则，字数统计同步更新。
- 结论：生成有加载态、结果回填与统计更新及时，「生成中不可重复点击」的反重复设计正确。

**场景③ 章节生成 —— ⏳ 待专项验证**
- 连续两次实测均在进入创作工作台后因代理步骤预算耗尽而中断，尚未完成大纲/章节生成的端到端验证。
- 该场景依赖已配置的智谱 API Key 完成真实调用，建议单独安排一次连贯会话专门验证流式输出、停止按钮与成功提示。

### 7.2 核心流程体验盘点（结合实测）
1. **新建项目 → 设定 → 生成章节** 链路完整，前两段已实测通过；世界观生成有明确的加载与回填反馈。
2. **生成中停止（H1 已修复）**：中止信号端到端贯通，降低长生成误操作成本。
3. **一致性报告 → 定位章节**：报告查看已具备，但从报告一键跳回章节仍需手动，可优化。

### 7.3 用户痛点（结合实测与代码评审）
- **加载反馈**：章节生成除进度条外建议补充当前阶段文案（设定/起草/校验）。
- **错误可恢复性**：生成失败提示较简单，建议提供「重试 / 保留已生成」两出口。
- **引导**：新用户首次进入缺少分步向导解释世界观/伏笔/记忆概念。
- **建议**：补一场连贯的「章节生成」专项实测后再定稿 SUS 评分。
