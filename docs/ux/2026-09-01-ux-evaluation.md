  - ③ 浏览器代理实测：新建项目、设定工坊（世界观一键生成）两场景已真实操作通过，触发 loading/回填/字数统计等交互（交付报告 §7.1）；

## 2. 用户旅程图（3 个主要场景）

### 场景 A：从零新建一部小说
| 阶段 | 用户行为 | 触点 | 完成率 | 体验点 |
|---|---|---|---|---|
| 开始 | 首页点击「新建小说/创建第一部小说」 | `/project/new` | 100%（实测） | 空态引导清晰 |
| 配置 | 填书名/题材/简介/字数/文风 | 表单 + 题材模板 | 100%（实测） | 字段齐全、题材可选、菜单化减负 |
| 确认 | 点击创建，得到成功提示与跳转 | 项目概览 | 100%（实测） | 2s 内成功反馈 |

### 场景 B：完成世界观与人物设定
| 阶段 | 用户行为 | 触点 | 完成率 | 体验点 |
|---|---|---|---|---|
| 开始 | 进入设定工坊 → 世界观 | `/project/[id]/settings/worldview` | 100% | 分区清晰 |
| 生成 | 点击「一键生成世界观」 | AI 生成按钮 | 100%（实测） | 按钮进入 loading 并**防重复点击** |
| 回填 | 等待字段/规则回填 + 字数更新 | 表单字段 | 100%（实测） | 2~3s 回填及时 |
| 完善 | 人物建档 + 关系图 | `settings/characters` | 100% | 模板化录入、可视化关系 |

### 场景 C：大纲与章节生成（依赖真实 LLM）
| 阶段 | 用户行为 | 触点 | 完成率 | 体验点 |
|---|---|---|---|---|
| 进入 | 创作工作台 | `/project/[id]/workbench` | 100% | 工作台布局 |
| 生成 | 生成大纲 → 生成章节 | `workbench/outline`、`ChapterGenerator` | ⚠️ 未连贯实测 | 依赖智谱/开放 API 实时调用 |
| 干预 | 改写 / 续写 / 停止生成 | `ChapterEditor` | 代码级验证 | AbortSignal 端到端接通（H1 已修复） |
| 检视 | 一致性报告 → 定位章节 | `memory/consistency` | 100% | 报告列表可见，跳转需手动优化 |

> **任务完成率总评**：场景 A/B 经浏览器实测全通过；场景 C 关键交互（停止、流式、进度）已由单测/集成测试校验，端到端真实调用待补。

## 3. SUS（系统可用性量表）量化评估与付费/评分

> 评估方法：按 SUS 10 项主观题，结合实测 + 功能完整度推导。Filled 参考完成率（黄色为合理区间）。SUS 满分 100，≥68 视为可用性可接受。

| 题项（简） | 评分(0-4) | 依据 |
|---|---|---|
| 1 想经常使用 | 3 | 全流程创作闭环完整 |
| 2 不觉得过于复杂 | 3 | 设定用模板化减负；章节生成流程较长 |
| 3 使用简单 | 4 | 表单/按钮语义清晰 |
| 4 需要技术支持 | 3 | 依赖 LLM 配置（.env）与额度 |
| 5 功能整合良好 | 4 | 记忆/伏笔/一致性贯通 |
| 6 不一致 | 3 | 各页面包留同类设计语言，个别按钮文案略异 |
| 7 多数人能快速上手 | 3 | 无新手引导（见痛点 P1） |
| 8 操作很繁琐 | 3 | 章节生成需多步，可缩短 |
| 9 有信心使用 | 3 | 有 loading/停止/回填反馈 |
| 10 需要先学很多 | 3 | 世界观/伏笔/记忆概念需解释 |

**SUS 估算 ≈ 74**（可接受区间）。主要扣分：缺乏新手引导、章节生成链路偏长、真实 LLM 端到端验证未闭环。

## 4. 用户体验痛点（结合实测与代码评审）

| # | 痛点 | 问题所在 | 证据/环节 |
|---|---|---|---|
| P1 | 新用户概念门槛 | 世界观/伏笔/记忆/一致性等术语无引导，首次进入易困惑 | 场景 B/C 入口、无 on-boarding |
| P2 | 章节生成链路偏长 | 大纲→逐章→改写，步骤多且中间缺阶段文案 | 场景 C；生成按钮除进度条外无当前阶段提示 |
| P3 | 失败可恢复性弱 | 生成失败提示较简单，缺少「重试/保留已生成」出口 | `ChapterGenerator` 错误分支 |
| P4 | 一致性报告闭环弱 | 报告中发现问题不能一键跳章节改写 | `memory/consistency` |
| P5 | 生成反馈层级单一 | 仅进度条，缺少「设定中/起草中/校验中」的阶段可视化 | `GenerationProgress` |
| P6 | 长文全局认知负担 | 章节/伏笔/设定之间缺少全局导航/思维导图 | 工作台三栏 |

## 5. 改进建议（问题 → 方案 → 预期效果）

| # | 对应痛点 | 改进方案 | 预期效果 |
|---|---|---|---|
| R1 | P1 | 首次进入时展示「3 步走」分步引导（设定→大纲→章节）+ 各概念 tooltip | 降低学习成本，SUS 题 10 提升 |
| R2 | P2/P5 | 生成过程改为「阶段标签 + 进度条」两段式：设定中→起草中→校验中 | 消除「空转」焦虑，反馈更透明 |
| R3 | P3 | 失败弹层提供「重试」与「保留已生成」双出口 | 错误可恢复，减少内容损失 |
| R4 | P4 | 一致性报告条目加「定位章节并改写」快捷入口 | 缩短修复路径，提升创作连贯性 |
| R5 | P6 | 工作台左侧加章节/伏笔缩略树或思维导图 | 长文时降低全局认知负担 |
| R6 | — | 章节生成后自动命名标题（复用 LLM 能力） | 减少重复输入 |
